# Learning notes — 02-rest-service

## Схема и миграции

**Решения.**
- Схема — только Flyway, Hibernate `ddl-auto: validate`: сущности проверяются против реальной схемы при старте,
  а не генерируют её. Миграции версионируются в Git и одинаково применяются в тестах, локально и в K8s
  (12-factor: XII admin processes).
- Инварианты дублируются в БД (`check`, `unique`, `foreign key`): приложение проверяет для понятной ошибки,
  БД — как последний рубеж против гонок.
- Уникальность без учёта регистра — функциональный индекс `lower(name)`, а не `unique` на колонке.
- Тесты — на настоящем PostgreSQL 17 (Testcontainers + `@ServiceConnection`), а не на H2: H2 не знает
  `jsonb`, ведёт себя иначе в блокировках и диалекте.

**Подводные камни.**
- `numeric(12,2)` + `BigDecimal`: Java-сторона должна сама отклонять 3 знака после запятой — иначе БД молча
  округлит.
- `timestamptz` хранит момент времени (UTC); `timestamp` без зоны — источник багов при смене часового пояса.
- Изменение уже применённой миграции ломает checksum Flyway — только новые миграции.

**Вопросы для собеседования.**
1. *Почему не `ddl-auto: update`?* — Неконтролируемые изменения схемы, нет отката и ревью; в production
   схема — артефакт, который версионируется.
2. *Почему Testcontainers, а не H2?* — Тестируем ту же БД, что в production: диалект, типы, ограничения,
   поведение транзакций.

## Contract-first

**Как устроено.** `catalog-api.yaml` (OpenAPI 3.1) пишется руками и лежит в `src/main/resources/static`.
`openapi-generator-maven-plugin` (`interfaceOnly`) генерирует `CategoriesApi`/`ItemsApi` и DTO в
`target/generated-sources`; контроллеры их реализуют. Нарушил контракт — код не компилируется. Ответы
(коды, заголовки, тела ошибок) дополнительно проверяет контрактный тест (задача 8): генератор видит только сигнатуры.

**Решения.**
- `If-Match` в контракте **необязателен**: при `required: true` сгенерированный код сам ответит `400`
  до нашего `428 Precondition Required`. Обязательность проверяет контроллер, контракт её документирует.
- Тело PATCH — свободный объект (`Map<String, Object>`): сгенерированный класс не отличил бы «ключа нет»
  от `null`, а в JSON Merge Patch это разные операции.
- Деньги в JSON — строка (`"12.50"`), не число: без потери точности на клиентах с `double`.
- `API-Version` не объявлен параметром каждой операции (иначе он попал бы в каждую сигнатуру),
  а описан в `info` и обрабатывается механизмом версионирования Spring.

**Подводные камни.** Поддержка OpenAPI 3.1 в openapi-generator всё ещё помечена как beta (предупреждение
при сборке); сложные конструкции 3.1 (`type: [string, "null"]`, `$defs`) лучше проверять по сгенерированному коду.

**Вопросы для собеседования.**
1. *Contract-first или code-first?* — Contract-first: API согласуется до реализации, клиенты генерируются
   параллельно, контракт — артефакт ревью. Code-first быстрее на старте, но контракт становится побочным
   продуктом аннотаций и легко ломается незаметно.
2. *Как поймать breaking change в API?* — Контракт в Git + diff-инструмент (openapi-diff) в CI; для
   code-first — сравнение сгенерированного документа с предыдущим.
