# ADR-0004: Нагрузка — Gatling (Java SDK), открытая модель, профиль «прогрев → пик → спад»

## Контекст и проблема

Нужна воспроизводимая «распродажа»: резкий рост заказов, удержание, спад, и автоматический вердикт. Генератор
работает с хоста (Windows/Git Bash) против кластера kind через Gateway.

## Движущие факторы

- Java-проект, Maven: тест как код в том же стеке.
- Вердикт — кодом выхода (assertions), отчёт — HTML.
- Распродажа — это **приходящие** покупатели, которые не ждут друг друга: модель по частоте прихода, а не по
  числу параллельных пользователей.

## Рассмотренные варианты

- A. **Gatling, Java SDK**, Maven-плагин
- B. k6 (JavaScript)
- C. JMeter
- D. Свой генератор на виртуальных потоках

## Решение

Выбран **A**.

- Отдельный Maven-модуль `12-scaling-operations/load` (Gatling 3.16, `gatling-maven-plugin`), запуск
  `./mvnw -f 12-scaling-operations/load/pom.xml gatling:test`.
- **Открытая модель** (`injectOpen`): прогрев 1 мин на низкой частоте → рост за 30 s до пика → пик 3 мин →
  спад 1 мин. Частоты — параметры (`-Dpeak=…`), стартовые значения подбираются под ноутбук.
- Сценарий: `POST /api/orders` со смесью покупателей и товаров (в основном успешные, часть — отказ по лимиту или
  складу, оба стиля саги), сохранение id заказа из ответа в файл для сверки (ADR-0001).
- **Склад под распродажу**: сид 11 (`ANVIL-01` 10, `HAMMER-01` 25) кончается за десятки заказов. Перед пиком
  `peak.sh` запускает Job `stock-refill` (psql в базе Inventory: `update stock_item set on_hand = …`) — код 11 не
  меняется, а Job — ещё один административный процесс (фактор XII, ADR-0007). Покупатели — сгенерированные
  (`peak-<n>`, лимит по умолчанию 500 EUR), чтобы не упираться в лимиты alice/bob; отказы задаются явно (bob,
  `TONGS-01`).
- Assertions — п. 3 ADR-0001; исход Gatling + сверка = вердикт.

### Последствия

- Хорошо: Java, Maven, HTML-отчёт, вердикт кодом выхода.
- Плохо: генератор на том же ноутбуке, что и кластер, отбирает CPU — потолок нагрузки ниже реального; это
  фиксируется в выводах.

### Подтверждение

`peak.sh` запускает Gatling и сверку; оба кода выхода — 0.

## Плюсы и минусы вариантов

### B. k6

- Хорошо: лёгкий, пороги в коде.
- Плохо: JavaScript, вне Java-стека.

### C. JMeter

- Хорошо: зрелый.
- Плохо: XML/GUI, тяжёлый, тест не как код.

### D. Свой генератор

- Хорошо: полный контроль.
- Плохо: свои ошибки измерения (coordinated omission), нет отчёта.
