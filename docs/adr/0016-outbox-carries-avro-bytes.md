# ADR-0016: В outbox лежат готовые байты Avro, Connect их не конвертирует

## Контекст и проблема

Debezium может выводить Avro сам (`AvroConverter` с реестром), но тогда схему строит Connect из структуры строки:
другое имя и namespace записи, и регистрирует схемы Connect — против решения 14 «схемами владеет пайплайн».

## Движущие факторы

- Сообщение в топике не отличается ни байтом от сообщения relay (контракт 14, Forge и pact-файл не меняются).
- Схемы регистрирует только пайплайн.

## Рассмотренные варианты

- **Байты в `payload bytea`, `ByteArrayConverter`.**
- JSON в payload и `AvroConverter` в Connect.
- Debezium внутри приложения.

## Решение

Выбран **вариант с байтами**: Ordering сериализует тем же сериализатором Apicurio и той же конфигурацией, что relay
(явная версия схемы, id схемы в теле). Event Router отвечает только за топик, ключ и заголовки.

### Последствия

- Хорошо: Forge не замечает смену способа доставки; `OutboxBytesIT` это доказывает.
- Плохо: Ordering обращается к реестру внутри транзакции заказа — реестр недоступен → заказ не принят (503).
- Плохо: содержимое outbox не читается глазами (бинарное), для отладки — десериализатор или Forge.
