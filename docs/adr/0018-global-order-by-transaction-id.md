# ADR-0018: Глобальный порядок чтения — (tx_id, position) ниже xmin снимка

## Контекст и проблема

Проекции читают весь журнал по checkpoint. `global_position` (`bigserial`) выдаётся при вставке, а видимым событие
становится при коммите. Две параллельные транзакции: позиция 5 коммитится позже позиции 7 — читатель, дошедший до 7,
пропустит 5 навсегда.

## Рассмотренные варианты

- **`tx_id xid8 = pg_current_xact_id()` в строке, чтение `(tx_id, position) > checkpoint` и
  `tx_id < pg_snapshot_xmin(pg_current_snapshot())`.**
- Сериализовать запись (advisory lock на весь журнал) — порядок вставки = порядок коммита.
- Читать с «окном» (не брать события моложе N секунд) — эвристика, теряет при долгих транзакциях.

## Решение

Выбран **tx_id ниже xmin**: читатель берёт только события транзакций, которые старше любой ещё открытой, и
упорядочивает по `(tx_id, position)`; checkpoint хранит пару. Пропуск невозможен, параллельная запись сохраняется.
Проверено `EventStoreIT.readAllWaitsForOpenTransactions` и `readAllLosesNothingBetweenPositionsOfOneTransaction`.

### Последствия

- Хорошо: нет глобальной блокировки записи; корректно при любом числе писателей.
- Плохо: долгая открытая транзакция в БД (любая, не только запись в журнал) задерживает все проекции; `xid8` —
  PostgreSQL 13+. Порядок внутри журнала — порядок транзакций, а не времени `recorded_at`.
