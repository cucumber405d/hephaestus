# ADR-0010: Границы модулей проверяет Spring Modulith; модули общаются событиями и владеют своими таблицами

## Контекст и проблема

Легаси-«Мастерская» разбита на пакеты по предметным областям, но внутри они переплетены: цикл ordering ↔ forge,
чужие таблицы, общая транзакция (`13-modular-monolith/legacy/README.md`). Прежде чем выносить сервис, монолит надо
привести в порядок так, чтобы порядок проверялся автоматически, а не держался на дисциплине.

## Движущие факторы

- Границы должны проверяться тестом, а не ревью.
- Каждый модуль можно тестировать отдельно.
- Поведение после модуляризации такое же, как у легаси (те же сценарии).

## Рассмотренные варианты

- **Spring Modulith**: модули — пакеты верхнего уровня; `ApplicationModules.verify()`, `@ApplicationModuleTest`,
  `Scenario`, Documenter; события через реестр публикаций (тот же outbox, что в 10).
- **ArchUnit-правила вручную** (как в 02).
- **Maven-модули на каждый контекст.**

## Решение

Выбран **Spring Modulith**. Он знает, что такое модуль, его API и `internal`. Он проверяет и циклы, и доступ к
внутренностям, тестирует модуль отдельно и рисует диаграммы. События после коммита дают ту же асинхронность, что
будет у вынесенного сервиса, но внутри одного процесса.

Правила:
- API модуля — типы в корне его пакета, всё остальное — `internal`.
- **Типы событий обоих направлений — в API модуля, которому они адресованы** (`forge`): `WorkOrderRequested`,
  `WorkOrderCompleted`, `WorkOrderFailed`. Если тип события лежит в модуле-слушателе, зависимость остаётся, и цикл
  ordering ↔ forge вернулся бы. События сами по себе цикл не убирают.
- **Модуль владеет своей схемой PostgreSQL** (`ordering`, `inventory`, `forge`, `migration`); чужие таблицы не
  читаются и не пишутся. Modulith этого не видит (SQL — не зависимость Java), поэтому это правило ADR и ревью.
- Вынесенный сервис — гексагональный, как 02; там направление зависимостей проверяет ArchUnit.

### Последствия

- Хорошо: `ModularStructureTest.verifyPasses` охраняет границы; модули проверяются по отдельности.
- Плохо: поведение стало асинхронным (заказ на мифрил отклоняется не в том же запросе, а событием), клиенты
  опрашивают статус. Это та же цена, что потом заплатит сервис, но видна она раньше.
- Плохо: правило «своя схема» держится на ревью.

### Подтверждение

`ModularStructureTest`, `ForgeModuleTest`, `OrderingModuleTest`, `ModularFlowIT` (сценарии легаси), диаграммы в
`13-modular-monolith/docs/modules/`, таблица `docs/legacy-to-modular.md`.
