# ADR-0007: Аудит 12 факторов — таблица с доказательствами и административный процесс как CronJob

## Контекст и проблема

Корневая спека обещает пройти Twelve-Factor App (и «15 factors») по подпроектам. В 12 — итоговый аудит:
где каждый фактор выполнен, где нарушен, чем доказывается. Фактор XII (административные процессы) пока
закрыт только Flyway-Job из 04.

## Движущие факторы

- Аудит должен быть проверяемым: ссылка на файл, команду или тест, а не «да».
- Честность: нарушения фиксируются, а не прячутся.

## Рассмотренные варианты

- A. **Документ-таблица** `12-scaling-operations/docs/twelve-factor-audit.md` + один новый CronJob
- B. Только документ
- C. Автоматический линтер (например, проверки манифестов) — вне рамок

## Решение

Выбран **A**.

- Таблица: фактор → статус (✔ / частично / ✘) → доказательство (путь, команда) → подпроект → что не так.
- **XII**: `CronJob` очистки outbox — удаляет завершённые публикации старше 1 дня из `event_publication`
  каждого сервиса (через `psql` в образе PostgreSQL, тот же секрет CNPG). Одноразовый — `Job` «пересчёт
  статистики» не делаем: CronJob достаточно, чтобы показать фактор.
- VIII (concurrency) доказывается прогоном 12: масштаб процессов, а не потоков.

### Последствия

- Хорошо: аудит — готовый материал для портфолио и собеседования.
- Плохо: таблицу надо обновлять в будущих подпроектах (13–22).

### Подтверждение

Ревью таблицы; CronJob виден в `kubectl get cronjob -n hephaestus-12`, последний запуск успешен.
