# ADR-0015: Доставка outbox через CDC (Debezium), relay из приложения — для сравнения

## Контекст и проблема

В 10, 13 и 14 outbox — таблица публикаций Spring Modulith, отправляет само приложение после коммита. Если отправка
не удалась (Kafka недоступна, сервис убит), событие повторяется только при следующем старте сервиса.

## Движущие факторы

- Доставка не должна зависеть от того, жив ли сервис-отправитель.
- Атомарность «состояние + событие» сохраняется.
- Сравнение с подходом 10 — на одном потоке, отказами, а не словами.

## Рассмотренные варианты

- **Debezium PostgreSQL connector в Kafka Connect + Outbox Event Router.**
- Debezium Server / embedded engine рядом с приложением.
- Relay с повтором по расписанию (`IncompleteEventPublications`).

## Решение

Выбран **Debezium в Kafka Connect** (Strimzi на платформе). Relay из 14 остаётся режимом `OUTBOX_MODE=modulith`,
без доработок — сравнивается именно подход 10. Учения отказов показывают разницу.

### Последствия

- Хорошо: событие уходит, даже когда сервис лежит; один механизм на все сервисы.
- Плохо: новый компонент платформы (Connect), логическая репликация, слот держит WAL, права REPLICATION.
- At-least-once: потребители идемпотентны (уже так с 13).
