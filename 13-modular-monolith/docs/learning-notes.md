# 13-modular-monolith — выводы

## Modulith видит не всё

Из четырёх узлов легаси Spring Modulith ловит один — цикл ordering ↔ forge. Чужая таблица через SQL, протекающая
модель поставщика, HTTP-вызов внутри транзакции — не зависимости Java-пакетов. Проверка границ кода необходима, но
недостаточна: остальное держат ADR («модуль владеет своей схемой»), ACL и ревью.

## События не убирают цикл сами

Первая версия модульного монолита: `WorkOrderRequested` в `ordering`, `WorkOrderCompleted` в `forge`, каждый слушает
чужое событие. Для Modulith это снова цикл — тип события тоже зависимость. Решение: все типы событий взаимодействия
— в API модуля, которому они адресованы (`forge`). Зависимость одна, ordering → forge.

## Модульный монолит показывает цену выноса заранее

После модуляризации заказ на мифрил отклоняется не в том же запросе, а событием через мгновение. Тесты ждут,
клиенты опрашивают. Это ровно та асинхронность, которую потом принесёт сервис — но обнаруженная внутри одного
процесса, где её дешевле осмыслить.

## Переключатель — не переменная окружения

Первая мысль — `FORGE_CUTOVER=true` в Deployment. Проверка спеки показала: при рестарте пода Modulith заново
доставляет незавершённые публикации, и событие, опубликованное «до», обработалось бы по правилу «после» — потеря или
дубль. Решение: флаг в базе, читается **в транзакции заказа**, результат записан в **тип события**
(`WorkOrderRequested` / `RemoteWorkOrderRequested`). Повторная доставка не может передумать.

## Маршрут, который не меняется

Если при переключении меняются и флаг, и маршрут, они применяются в разные моменты, и запросы теряются в щели.
Статический маршрут с первого дня (`WO-` → монолит, остальное → сервис-фасад) сводит переключение к одному флагу.
Envoy Gateway умеет регулярку в пути, но не в заголовках — поэтому старые и новые заказы различаются форматом id.

## Spring Modulith и Kafka: JSON с двух сторон

`spring.modulith.events.kafka.enable-json` (по умолчанию включено) ставит JSON-конвертер не только на отправку
(`@Externalized`), но и на фабрику слушателей. Слушатель с параметром `String` получал «Cannot deserialize String
from Object». Слушатели принимают записи — конвертер разбирает их сам.

## Финальное ревью нашло дыру в собственной гарантии

«Вывод Forge из эксплуатации отклоняется, пока есть открытые заказы» — недостаточно. Запрос, опубликованный до
переключения, может ещё не стать заказом: слушатель не успел, упал или ждёт переотправки после рестарта. Тогда
после вывода появлялся `WO-`, с которым никто не может работать. «Занятость» Forge — это открытые заказы **плюс
незавершённые публикации** из реестра Modulith. Кроме того, флаг читается `for share`, проверка и смена состояния
выполняются в одной транзакции (`PendingRequestIT`). Урок: outbox переносит «работу в полёте» в таблицу, и любые
проверки «ничего не осталось» обязаны смотреть и туда.

## Kafka по умолчанию молча пропускает

`DefaultErrorHandler` без настройки делает 10 попыток подряд без пауз и коммитит смещение: рестарт базы на пару
секунд — и заявка или исход потеряны. Здесь: растущая пауза до `KAFKA_RETRY_MAX_ELAPSED` (5 мин), затем
`<topic>.DLT`; «ядовитые» сообщения — в DLT сразу (`KafkaErrorHandling`).

## Boot 4 и Jackson 3 мелочи

- `RestClient.Builder` — в отдельном стартере `spring-boot-starter-restclient`.
- Jackson 3 по умолчанию отказывается от отсутствующего значения для примитива (`FAIL_ON_NULL_FOR_PRIMITIVES`):
  поля запросов — обёртки (`Boolean`, `Integer`).

## Вопросы для собеседования

1. С чего начинать распил монолита? (С модуляризации внутри и автоматической проверки границ; вынос — когда модуль
   уже живёт как отдельный.)
2. Что делать с данными при Strangler Fig? (Варианты A/B/C из ADR-0009; почему для долгих процессов — «старые
   доживают».)
3. Чем Spring Modulith отличается от ArchUnit? (Знает модель модулей, API/internal, тестирует модуль отдельно,
   события и outbox; ArchUnit — правила про классы и пакеты.)
4. Зачем ACL, если можно просто использовать классы поставщика?
5. Как откатить переключение? (Флаг обратно; созданное в новой системе доживает там — симметрия варианта A.)
6. Как доказать, что при переезде ничего не потерялось? (Сверка по данным обеих систем, а не по логам и метрикам.)
7. Почему решение «куда отправить» принимается при публикации, а не при доставке?
