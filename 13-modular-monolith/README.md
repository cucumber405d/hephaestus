# 13-modular-monolith — от монолита к сервисам

История миграции легаси-монолита, рассказанная кодом: «Мастерская Гефеста» в трёх стадиях **рядом**, чтобы каждую
можно было собрать, запустить и сравнить.

| Стадия | Модуль | Что показывает |
|---|---|---|
| 0 | [`legacy/`](legacy/README.md) | Одно приложение, одна схема, четыре узнаваемых узла. Spring Modulith `verify()` красный — и это закреплено тестом |
| 1 | `modular/` | Те же функции: модули Spring Modulith, свои схемы, события между модулями, ACL к поставщику. `verify()` зелёный ([нарушение → лечение](docs/legacy-to-modular.md), [диаграммы](docs/modules/)) |
| 2 | `forge-service/` | Forge вынесен по Strangler Fig, вариант «новые в новый, старые доживают в старом»: переключение флагом без рестарта, сверка «ровно один заказ на ковку» |

Плюс `supplier-stub/` (внешний поставщик с легаси-протоколом: XML, немецкие поля, коды 0/17/42) и `traffic/`
(генератор заказов и «кузнец-бот» для прогонов переключения).

**Решения:** [ADR-0009](../docs/adr/0009-strangler-fig-new-to-new.md) (Strangler Fig, данные),
[ADR-0010](../docs/adr/0010-module-boundaries-and-events.md) (границы модулей),
[ADR-0011](../docs/adr/0011-anti-corruption-layers.md) (ACL).

**Документы:** [start](docs/start.md) — команды; [architecture](docs/architecture.md) — стадии и переключение
диаграммами; [learning-notes](docs/learning-notes.md) — выводы и вопросы для собеседования.
