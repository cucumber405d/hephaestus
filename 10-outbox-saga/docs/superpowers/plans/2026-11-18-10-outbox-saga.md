# 10-outbox-saga Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Order saga Ordering → Payment → Inventory → Delivery in choreography and orchestration side by side, every outgoing message through a Spring Modulith outbox.

**Architecture:** Four small services, one uniform message record (`SagaMessage`, JSON string values, `type` field) on per-service topics keyed by `orderId`. Participants run the same business action for both styles; the style only decides where input comes from and where the result goes. Orchestrator lives in Ordering (`saga` table, pure `Orchestrator` decisions, scheduled step timeouts).

**Tech Stack:** Java 25, Boot 4.1.2, Spring Kafka 4, Spring Modulith 2.1 (`spring-modulith-starter-jdbc`, `spring-modulith-events-kafka`), JdbcClient, Flyway, PostgreSQL 17, Kafka 4.2.2, Kafka UI, Testcontainers 2.

**Spec:** `10-outbox-saga/docs/superpowers/specs/2026-11-18-10-outbox-saga-design.md`

## Global Constraints

- Packages `de.ibikus.appa.hephaestus.outboxsaga.<service>`; artifactIds `outbox-saga`, `outbox-saga-<service>`; images `hephaestus/outbox-saga-<service>`; Compose project `hephaestus-10`.
- `SagaMessage(UUID messageId, String type, UUID orderId, String saga, String customerId, BigDecimal amount, List<Line> lines, String reason, Instant at)`; `Line(String sku, int quantity)`.
- Topics (3 partitions, key orderId): `ordering.events`, `payment.events`, `inventory.events`, `delivery.events`, `payment.commands`, `inventory.commands`, `delivery.commands`, `ordering.replies`.
- Events: OrderPlaced, PaymentReserved, PaymentDeclined, PaymentRefunded, StockReserved, StockUnavailable, StockReleased, DeliveryScheduled, DeliveryFailed, DeliveryCancelled. Commands: ReservePayment, RefundPayment, ReserveStock, ReleaseStock, ScheduleDelivery, CancelDelivery.
- Outbox: publish `OutgoingMessage(topic, SagaMessage)` via `ApplicationEventPublisher` inside the state-changing transaction; `EventExternalizationConfiguration` routes to `topic` with key `orderId`, maps to JSON string; scheduled resubmission of incomplete publications older than 10 s every 10 s; producer `max.block.ms` 5000.
- Idempotency: `processed_message(message_id)` per participant, `insert … on conflict do nothing` in the handling transaction.
- Step timeout `saga.step-timeout` 30 s (tests: 3 s). Ports 8080–8083, Kafka UI 8085.
- English comments; impact per commit; no k8s.

## Review Focus

1. Reply arriving after a timeout or out of step (late/duplicate) → ignored, no second compensation — Task 5 unit test.
2. Delivery down during orchestration → timeout → ReleaseStock + RefundPayment + CancelDelivery; when Delivery comes back it schedules then cancels (same partition order) — Task 5 test + e2e 7.
3. Kafka down at order time → 202, publication incomplete, delivered after Kafka returns — Task 5 IT + e2e 5.
4. Refund/release without prior reservation or twice → no-op, no negative balances — Task 2/3 tests.
5. Choreography message with `saga=orchestration` (and vice versa) never triggers an action — Task 2 test.

### Task 2: Payment
Accounts (seed alice 1000, bob 50, default 500 on first use), `payment_reservation(order_id pk, amount, status)`. `reserve` (once per order; declined if limit − reserved < amount), `refund` (no-op unless RESERVED). Listener: choreo OrderPlaced(saga=choreography) → PaymentReserved/Declined on `payment.events`; StockUnavailable/DeliveryFailed (choreo) → refund → PaymentRefunded; orch ReservePayment/RefundPayment → reply on `ordering.replies`. Tests: rules, duplicate messageId, wrong style ignored, IT command → reply.

### Task 3: Inventory
Stock seed (ANVIL-01 10, HAMMER-01 25, TONGS-01 0), `stock_reservation`. Choreo PaymentReserved → StockReserved/StockUnavailable; DeliveryFailed → release → StockReleased; orch ReserveStock/ReleaseStock. Tests as Task 2.

### Task 4: Delivery
`delivery(order_id pk, status SCHEDULED|CANCELLED)`; fails for `failCustomers`. Choreo StockReserved → DeliveryScheduled/DeliveryFailed; orch ScheduleDelivery/CancelDelivery (cancel of unknown → remembered as CANCELLED so a late schedule is refused). Tests.

### Task 5: Ordering — orders, choreography tracking, orchestrator, outbox
Orders + history + `saga` table; `POST /api/orders` 202, `GET /api/orders/{id}`; `POST /admin/republish/{id}`. Pure `Orchestrator` (state × reply → next state + commands; timeout → compensations). Choreo tracker sets CONFIRMED/REJECTED. Scheduled timeouts. Tests: orchestrator unit (all transitions, RF1, RF2), IT outbox (publication row in transaction, record on topic; Kafka-down resubmission if feasible), IT orchestration with replies sent by the test.

### Task 6: Compose + e2e
One Postgres with init script (4 databases), Kafka 4.2.2, Kafka UI, 4 services. e2e: scenarios 1–7 × both styles.

### Task 7: Docs + final review
README, start (scenarios by hand), architecture (both sagas as sequence diagrams, outbox), learning notes (comparison table, outbox vs CDC, compensations/semantic locks, timeouts, Temporal/Camunda), review (opus), fix pass.
