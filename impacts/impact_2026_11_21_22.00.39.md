**RU.** Стадия 1 подпроекта 13: та же «Мастерская», разрезанная на модули Spring Modulith.
- У каждого модуля своя схема PostgreSQL.
- Ordering и Forge общаются событиями после коммита; реестр публикаций работает как outbox.
- Типы событий обоих направлений лежат в API `forge`, поэтому цикла нет.
- Поставщик спрятан за ACL: коды 0/17/42 переводятся в `Delivered`, `PermanentFailure`, `TransientFailure`. У вызова
  есть таймаут, а недоступность поставщика означает «ждём материал» с повтором.

Тесты: `verify()` зелёный, Documenter пишет диаграммы в `docs/modules`, модули проверяются по отдельности через
`@ApplicationModuleTest` и `Scenario`, сквозной поток повторяет случаи легаси, плюс отдельно ACL и API кузнеца.
Таблица «нарушение → лечение» — в `docs/legacy-to-modular.md`.

**EN.** Stage 1 of 13: modules with their own PostgreSQL schemas, events after commit (publication registry as
outbox), all event types in forge's API (no cycle), Supplier behind an ACL with timeout and retry. verify() green,
Documenter output, module tests with Scenario, the legacy cases end to end, ACL and smith API tests, cure table.
