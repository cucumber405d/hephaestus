RU: Inventory и Ordering — OAuth2 Resource Server без состояния. Токен проверяется по `iss` (публичный адрес Keycloak),
ключам с внутреннего адреса и `aud`. Роли берутся из `realm_access.roles` (`RealmRolesConverter` → `ROLE_*`).
- Inventory: склад читает любой аутентифицированный, резервирует только роль `inventory-reserver` (сервисный аккаунт Ordering).
- Ordering: заказ создаёт только `customer`; заказ хранит `customer_id` = `sub`; чужой заказ — 404 (как несуществующий), admin видит все.
- Ordering → Inventory: собственный токен по client credentials (`OAuth2ClientHttpRequestInterceptor`, кэш токена);
  отказ Keycloak → 503 как недоступность Inventory.
Тесты: `jwt()` из spring-security-test, заглушка token endpoint в `StubInventoryServer`.

EN: Both services validate JWTs (issuer, internal JWKS, audience) and map Keycloak realm roles. Orders are owned by the
token subject (foreign → 404, admin sees all). Ordering calls Inventory with its own client-credentials token.
