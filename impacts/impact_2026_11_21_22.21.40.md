**RU.** Ядро стадии 2: Forge как отдельный сервис, гексагональный, как в 02. Порты: хранилище заказов, склад
материалов, поставщик, исходы. ArchUnit проверяет направление зависимостей: то, что внутри монолита проверял
Modulith, здесь проверяет ArchUnit.
- У сервиса своя база и своя доля склада материалов, заполняемая при развёртывании: «склад делится при переезде».
- Id заказов — `FW-<uuid>`.
- API кузнеца совпадает с монолитом путь в путь, `origin` = `SERVICE`.
- ACL к поставщику скопирован, а не вынесен в общую библиотеку (правило корневой спеки).
- Повторный запрос на тот же заказ клиента ничего не создаёт: уникальный `order_id`.

**EN.** Stage 2 core: Forge as a hexagonal service (ports for store, stock, supplier, outcomes; ArchUnit rules), its
own database and material share, FW- ids, the same smith API as the monolith (origin SERVICE), a copied Supplier ACL,
idempotent request per customer order.
