**RU.** Задача 2: `forge.event` — журнал только на дописывание (триггер запрещает UPDATE/DELETE/TRUNCATE),
оптимистичная конкуренция по `(stream_id, version)`, чтение всего журнала в порядке `(tx_id, global_position)` только
для транзакций старше `pg_snapshot_xmin` — проекция не может перескочить событие ещё открытой транзакции.
`read.projection_checkpoint(name, tx_id, position)`. Flyway Forge — `default-schema: public` (схема `forge` совпадает
с пользователем). `EventStoreIT` фиксирует оба сценария чередования транзакций.

**EN.** Task 2: `forge.event`, an append-only journal (a trigger refuses UPDATE/DELETE/TRUNCATE), optimistic
concurrency on `(stream_id, version)`, a global read in `(tx_id, global_position)` order below `pg_snapshot_xmin`, so a
projection can never skip an event of a still open transaction; checkpoint table; Forge's Flyway keeps its history in
public. EventStoreIT pins both interleavings.
