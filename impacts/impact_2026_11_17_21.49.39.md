description: Ordering резервирует товар в Inventory через @HttpExchange-клиент с таймаутами; ошибки соседа → 409/422/503 + Retry-After.
---

**RU.** Ordering: `POST /api/orders` (резерв в Inventory, затем сохранение заказа — удалённый вызов вне транзакции
БД), `GET /api/orders/{id}`, `GET /api/orders/availability/{sku}` (склад v2). Клиент — интерфейс `InventoryHttpApi`
(`@PostExchange` v1, `@GetExchange` v2) через `HttpServiceProxyFactory` над `RestClient`: JDK HttpClient, connect 1 s,
read 2 s, HTTP/1.1, заголовок `API-Version`. Адаптер переводит ответы: 409 → нехватка (SKU из Problem Details),
404/422 → неизвестный товар, 5xx/отказ соединения/таймаут → недоступность → наш 503 + `Retry-After: 5`. Тесты:
сервис на фейке, настоящий клиент против заглушки на JDK `HttpServer` (версии, коды, закрытый порт, медленный
ответ), web slice, IT на PostgreSQL с заглушкой; ArchUnit.

**EN.** Ordering service with an HTTP interface client to Inventory (explicit timeouts, API-Version per method),
error translation to 409/422/503 + Retry-After; tests against a JDK HttpServer stub and PostgreSQL.
