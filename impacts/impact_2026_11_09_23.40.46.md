**RU.** `CatalogScenarioIT` проходит путь клиента (категория → изделие → поиск → PATCH → устаревший PUT → DELETE)
и проверяет каждый запрос и ответ против `catalog-api.yaml`; проверка мутацией подтвердила, что валидатор сам ловит
неверный код ответа. Версия API выбирается заголовком `API-Version` (поддерживается `1`, по умолчанию), иная —
`400 unsupported-api-version`. Ключи идемпотентности старше 24 часов удаляются раз в час. Swagger UI показывает
рукописный контракт, генерация документации из кода выключена. Параметр `sort` стал одной строкой через запятую
(`sort=-price,name`) — так его понимает и валидатор контракта. Добавлены `requests.http` и итоговая документация
(архитектурная диаграмма, learning-notes).

**EN.** Contract-validated client journey (mutation-checked), header-based API versioning, hourly cleanup of
idempotency keys, Swagger UI on the hand-written contract, comma-separated sort parameter, HTTP request samples
and final architecture and learning notes. 90 unit and 29 integration tests green.
