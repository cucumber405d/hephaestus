# 08-resilience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Inventory reads offers from a flaky Supplier through three side-by-side resilience mechanisms (Resilience4j, Spring Cloud Circuit Breaker, Spring 7 built-in) with a Redis fallback, proven by Testcontainers ITs with Toxiproxy and a Compose e2e.

**Architecture:** Copy of 06 Inventory plus a new Supplier service. One out-port `SupplierOffers`, three adapters (one per mechanism) over one shared `@HttpExchange` client; the application service owns the cache write and the cache fallback, so the adapters differ only in how they protect the call.

**Tech Stack:** Java 25, Spring Boot 4.1.2, Spring Cloud 2025.1.3, Resilience4j 2.x, Spring Data Redis, Testcontainers 2 (Redis, Toxiproxy, PostgreSQL), Toxiproxy, Jib.

**Spec:** `08-resilience/docs/superpowers/specs/2026-11-18-08-resilience-design.md`

## Global Constraints

- Packages `de.ibikus.appa.hephaestus.resilience.{inventory,supplier}`; artifactIds `resilience`, `resilience-inventory`, `resilience-supplier`; images `hephaestus/resilience-{inventory,supplier}`; Compose project `hephaestus-08`.
- Same numbers for all mechanisms: read timeout 1 s, connect 500 ms; 3 attempts; backoff 200 ms ×2 with jitter; bulkhead 10. CB: sliding window 10 calls, failure rate 50 %, slow call > 800 ms, open 10 s, half-open 3 calls. Rate limiter (Resilience4j only): 20/s.
- Redis key `offer:{sku}`, TTL 10 min; written on every live answer; read only in fallback.
- English comments in code/YAML/scripts; impact file per commit; no k8s.

## Review Focus

1. Supplier 404 (unknown SKU) must reach the client as 404 and must NOT count as a CB failure or be retried — test per mechanism in Task 7.
2. Redis down: live answers still work (cache errors logged, ignored); fallback with Redis down → 503 — test in Task 3.
3. More than 10 concurrent calls: bulkhead rejects fast and the request falls back, no thread pile-up — test in Task 7 (r4j, spring).
4. Retry never applies to 4xx — covered by item 1 (Supplier call counter = 1).
5. Recovery: after the open interval a healthy Supplier closes the breaker — test in Task 7 (r4j, sccb).

### Task 3: Inventory supply core (port, cache, service, HTTP client)

**Files:** `domain/{SupplierOffer,UnknownOfferException,SupplierUnavailableException}.java`; `application/port/in/{SupplyQuery,SupplyAnswer,Mechanism}.java`; `application/port/out/{SupplierOffers,OfferCache}.java`; `application/service/SupplyService.java`; `adapter/out/supplier/{SupplierHttpApi,SupplierClientConfiguration,SupplierProperties}.java`; `adapter/out/cache/RedisOfferCache.java`.
**Produces:**
- `record SupplierOffer(String sku, BigDecimal price, String currency, int leadTimeDays, int maxQuantity)`
- `enum Mechanism { R4J, SCCB, SPRING }` (path value lower-case)
- `interface SupplierOffers { Mechanism mechanism(); SupplierOffer fetch(String sku); }` — throws `UnknownOfferException` (404) or `SupplierUnavailableException` (anything else, incl. CB open, bulkhead full, timeout)
- `interface OfferCache { void put(SupplierOffer o, Instant fetchedAt); Optional<CachedOffer> get(String sku); }`, `record CachedOffer(SupplierOffer offer, Instant fetchedAt)`
- `record SupplyAnswer(SupplierOffer offer, String source /*live|cache*/, Instant fetchedAt, Mechanism mechanism)`
- `SupplyService implements SupplyQuery { SupplyAnswer offer(Mechanism m, String sku) }`: live → cache.put → live; `SupplierUnavailableException` → cache.get → cache answer or rethrow; `UnknownOfferException` → rethrow (no cache).
- `SupplierHttpApi` `@GetExchange("/api/offers/{sku}") SupplierOffer offer(@PathVariable String sku)`; client built like 06's Inventory client (JDK HttpClient HTTP/1.1, connect 500 ms, read 1 s) from `supplier.url` (`SUPPLIER_URL`).
- [ ] Tests (`SupplyServiceTest` with fakes): live answer cached; unavailable + cache → source `cache` with old `fetchedAt`; unavailable + empty cache → `SupplierUnavailableException`; unknown → `UnknownOfferException`, cache untouched; cache throwing on put/get → live still returned / fallback → unavailable (Review Focus 2).
- [ ] `RedisOfferCache` with `StringRedisTemplate` + Jackson JSON, TTL 10 min, catch `DataAccessException` → log WARN, behave as miss. IT `RedisOfferCacheIT` (Testcontainers Redis): put/get roundtrip, TTL ≤ 600 s.
- [ ] Commit `feat(08): supply port, Redis cache, Supplier HTTP client`.
